THE DIAGNOSIS

THE FAILURE WAS
ARCHITECTURAL.

The answer was not wrong because it was free. It was ungrounded because the path ended at text.

01

No retrieval contract

The system was not required to find evidence, resolve identities, or challenge the premise.

02

No observation loop

Nothing happened after the answer, so there was no real-world feedback to correct it.

03

No permission boundary

A completion has no explicit policy for what may be read, changed, executed, or blocked.

04

No proof of work

There was no diff, command output, test result, citation ledger, or accountable reviewer.

WHAT THE HARNESS ADDS

MORE CAPABILITY.
MORE RESPONSIBILITY.

A harness can make work observable and governable. It cannot make an autonomous action automatically correct.

CONTEXT

Rules before edits

Repository instructions and project rules shape the task before code changes begin.

TOOLS

Actions with consequences

Files, terminal commands, browser operations, and integrations turn text into real work.

GUARDRAILS

Permissions and hooks

Command policies and lifecycle hooks can block, validate, log, or enrich operations.

EVIDENCE

Checks that can be inspected

Diffs, test output, build results, citations, and traces create an audit trail.

REVIEW

A human still decides

The final diff and reported checks must be reviewed before merge, release, or reliance.

AUTONOMY WARNINGThe default task path uses auto-approval and can edit files or run commands. This wrapper is not a sandbox. Use a clean branch, keep permissions narrow, and review the evidence.
